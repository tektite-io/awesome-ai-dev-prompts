<guidelines>
- Enforce clean separation between MCP Capabilities: Resources (read-only data streams), Tools (executable actions with side effects), and Prompts (reusable contextual templates).
- Use strict Zod (TypeScript) or Pydantic (Python) schemas for tool parameters, ensuring every input property contains explicit descriptions and type definitions.
- Implement robust error handling conforming to JSON-RPC 2.0 specifications; return standard error codes (`-32602` for invalid params, `-32603` for internal error) alongside human-readable diagnostics.
- DO: Implement resource templates with dynamic URI patterns (`config://{environment}/settings`) to let clients inspect state declaratively.
- DO: Support bidirectional progress reporting (`notifications/progress`) for long-running tool executions to keep AI clients informed during batch operations.
- DON'T: Expose raw database connection strings or unauthenticated shell execution endpoints directly as MCP tools; wrap them in strict operational interfaces.
- DON'T: Mix stdio logging with transport streams; direct all application logs to stderr so stdin/stdout remain pure JSON-RPC protocol channels.
</guidelines>
